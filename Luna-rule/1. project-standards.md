# Luna Project Standards & Engineering Guidelines

This document defines the mandatory engineering standards, naming conventions, database design patterns, and API specification templates for the **Luna** microservices project.

---

## 1. Folder & File Naming Conventions

All directories and files within the workspace must strictly follow these regular naming patterns:

### 1.1 Top-Level Folders
Top-level folders must follow consistent capital `Luna-` prefixing:
- **`Luna-plan/`**: Architecture blueprints, implementation roadmaps, and technical RFCs.
- **`Luna-api-spec/`**: API specifications for all microservice endpoints.
- **`Luna-platform/`**: Database design, DDL schemas, and seed DML scripts.
- **`Luna-rule/`**: Engineering rules, coding standards, and project constraints.
- **Backend Service Modules**: Standard multi-module names: `luna-gateway/`, `product-service/`, `user-service/`, `order-service/`.
- **Frontend App**: `frontend/`.

### 1.2 Subdirectory & File Naming
- **Subdirectories**: Always lowercase kebab-case (e.g., `product-service/`, `user-service/`, `order-service/`, `db/ddls/`, `db/dmls/`).
- **API Spec Files**: Lowercase kebab-case describing the action (e.g., `list-products.md`, `get-product-by-id.md`, `place-order.md`).
- **DDL SQL Files**: Numbered prefix with descriptive domain name (e.g., `1. products.sql`, `2. users.sql`, `3. orders.sql`).

## 2. Database Design & DDL Rules

All database schemas in `Luna-platform/db/ddls/` must follow the exact structure established in `1. products.sql`. Constraints and indexes **must be explicitly grouped immediately after each table design**:

### 2.1 Table Definition Pattern
For every table:
1. **`CREATE TABLE IF NOT EXISTS <table_name>`**:
   - Declare core columns with explicit data types and default values.
   - `id`: Always `uuid primary key default gen_random_uuid()` (or `bigserial primary key` for lookup categories).
   - Monetary values: Always `numeric(12, 2)` (never `float` or `double`).
   - Audit timestamps: Always `created_at timestamptz not null default now()` and `updated_at timestamptz not null default now()`.

2. **Constraints Grouped Immediately After Table Design**:
   - Foreign keys:
     ```sql
     alter table <table_name> 
         add constraint fk_<table_name>_<ref_table> 
         foreign key (<fk_column>) references <ref_table> (id);
     ```
   - Unique constraints:
     ```sql
     alter table <table_name> 
         add constraint unique_<table_name>_<column> unique (<column>);
     ```
   - Check constraints:
     ```sql
     alter table <table_name> 
         add constraint chk_<table_name>_<rule> check (<condition>);
     ```

3. **Indexes Grouped Immediately After Constraints**:
   - Explicit indexes on all foreign keys, unique keys, filtered columns, and sort columns:
     ```sql
     create index if not exists idx_<table_name>_<column> on <table_name> (<column>);
     ```

### 2.2 Template Example:
```sql
create table if not exists items (
    id uuid primary key default gen_random_uuid(),
    category_id bigint not null,
    name varchar(150) not null,
    price numeric(12, 2) not null,
    active boolean not null default true,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);

-- Constraints
alter table items 
    add constraint fk_items_category foreign key (category_id) references categories (id);
alter table items 
    add constraint chk_items_name_nonempty check (length(trim(name)) > 0),
    add constraint chk_items_price_positive check (price > 0.00);

-- Indexes
create index if not exists idx_items_category_id on items (category_id);
create index if not exists idx_items_active on items (active);
create index if not exists idx_items_created_at on items (created_at desc);
```

## 3. API Specification File Rules

All specification files inside `Luna-api-spec/` must adhere to the standard established in `list-products.md`:

### 3.1 Required Sections
1. **Title & Brief Summary**:
   - `# [Service / Domain] - [Feature / Action]`
   - 1–2 sentence summary explaining endpoint purpose.
2. **Section 1: Endpoint Metadata Table**:
   - Method, URL, Auth Required, Permission/Scope, Idempotent.
   - Base URL specification (Gateway port `8080` vs Direct service port).
3. **Section 2: Summary**:
   - Bulleted list of behaviors, database queries/mutations, business rules, and default sort orders.
4. **Section 3: Request Specifications**:
   - `3.1 Path Parameters` (Table with Name, Required, Type, Description or `NIL`).
   - `3.2 Query Parameters` (Table with Name, Required, Type, Default, Description or `NIL`).
   - `3.3 Headers` (Table with Name, Required, Description, Example).
   - `3.4 Body` (JSON schema/payload example or `NIL`).
5. **Section 4: Response Specifications**:
   - `4.1 Success - <HTTP Code> <HTTP Status>` (Formatted JSON payload example with realistic dress domain data).
   - `Notes:` explaining Enum values, calculated fields, and business constraints.
   - `4.2 Error Responses` (Markdown table with `HTTP`, `Error`, `Message`).

## 4. Architecture & Microservices Principles

1. **Strict Database Isolation**:
   - Each service owns its own database (`luna_products`, `luna_users`, `luna_orders`).
   - A service must NEVER connect to, query, or join another service's database directly.
2. **Synchronous Inter-Service Communication**:
   - Use Spring Cloud OpenFeign for REST calls between services (e.g., Order Service -> Product Service).
3. **Financial Immutability & Snapshots**:
   - Order items must record immutable snapshot values of `product_name`, `unit_price`, `size`, and `color`.
4. **Concurrency & Inventory Safety**:
   - Never use read-modify-write for stock. Always decrement stock with atomic conditional SQL:
     ```sql
     UPDATE product_variants SET stock_quantity = stock_quantity - :qty 
     WHERE id = :variantId AND stock_quantity >= :qty;
     ```
5. **Clean Code & DTO Separation**:
   - Java 21 Records for all Request/Response DTOs.
   - JPA entities must never be returned directly from REST controllers.
   - Centralized exception handling using RFC 7807 `ProblemDetail`.
